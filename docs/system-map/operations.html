    Gate check-in

    The scanner is a small web app that staff open on a phone. It is built to keep working when the hall's wifi does not: it holds the day's expected badges, records arrivals locally, and syncs when the connection returns.

    In the code
    • app/Http/Controllers/Checkin/CheckinController.phpScan, search, manual, offline sync
    • app/Services/TicketService.phpSigning and resolving a ticket
    15

    Messaging

    Nothing is sent while someone waits. Every message is written to the log first and queued second, so a registrant sees their confirmation page immediately and a failed send can be retried from the dashboard instead of being lost.

    Every message the system can send

    TemplateChannelSent when
    otpWhatsAppRegistration or sign-in — 6 digits, 10 minutes, 5 tries
    registration_confirmed_studentWhatsAppStudent verifies, with the badge attached
    registration_confirmed_parentWhatsAppParent verifies, with the badge attached
    registration_confirmed_visitorWhatsAppVisitor pass issued, with the badge attached
    event_reminder_3daysWhatsAppThree days before opening
    event_reminder_1dayWhatsAppThe day before
    day_of_directionsWhatsAppMorning of each day they chose
    session_reminderWhatsApp15 minutes before a saved session
    post_event_thankyou_surveyWhatsAppAfter the fair closes
    rsvp_confirmed · rsvp_pendingEmailConference RSVP, with or without the badge
    reminder_3days · reminder_1dayEmailDelegate reminders
    badge_resent · thankyouEmailOn request, and after the event

    Each row exists three times, once per language, and the wording is the same text submitted to Meta for template approval.

    Campaign QR codes

    Separate from badges: these are the codes printed on posters, banners and school handouts. Each is a short link that counts scans before forwarding, so it is possible to say which poster actually worked.
